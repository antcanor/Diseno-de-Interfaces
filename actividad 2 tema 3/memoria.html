A1. Primer Componente y Catálogo

En esta primera fase se ha diseñado e implementado el componente QuantityStepper en el paquete Flutter ui_kit_dam (ubicado en lib/src/quantity_stepper.dart). El widget proporciona un control intuitivo y estandarizado para la selección de valores numéricos discretos.

1.1 y 1.2 Implementación Inicial

El componente organiza visualmente en una fila horizontal (Row) un botón para decrementar con icono Icons.remove, un área central que muestra el valor numérico actual formateado y estilizado con la tipografía del tema, y un botón para incrementar con icono Icons.add.

Al pulsar el botón de adición el valor se incrementa en una unidad, y al pulsar el de sustracción se decrementa en una unidad, invocando internamente setState() para provocar el redibujado reactivo del widget.

1.3 Exportación en la Biblioteca

Para mantener una arquitectura modular limpia con aislamiento del directorio src/, el componente se exporta directamente desde el archivo de barrera principal lib/ui_kit_dam.dart: 

library;

export 'src/info_badge.dart';

export 'src/star_rating.dart';

1.4 Integración en Widgetbook ("Por defecto")

Se ha configurado el catálogo de componentes Widgetbook en el archivo widgetbook/widgetbook.dart, permitiendo previsualizar el caso de uso "Por defecto" en un entorno aislado donde se instancia QuantityStepper() con sus valores iniciales predeterminados (rango 0 a 10, valor 0).

Pregunta A1.5 de la Tarea: ¿Por qué este componente es un StatefulWidget e InfoBadge no?

En el modelo de renderizado reactivo de Flutter, la elección entre un StatefulWidget y un StatelessWidget responde a la necesidad de gestionar o no un estado mutable a lo largo del tiempo:

  • QuantityStepper es un StatefulWidget porque mantiene un ciclo de vida con datos internos dinámicos (la variable privada _value) que mutan directamente como resultado de la interacción del usuario (pulsación de los botones + y −). El widget delega su lógica en un objeto asociado de tipo State<QuantityStepper>, el cual invoca setState() para encolar la reconstrucción del subárbol de widgets mostrando el nuevo número sin requerir que un widget ancestro le reinyecte dicho valor.
  • InfoBadge es un StatelessWidget porque es un componente puramente presentacional e inmutable. Su función es exclusivamente proyectar en pantalla la información que recibe desde su constructor (como el texto de la etiqueta label, el color y el icono opcional icon). Dado que la insignia no almacena datos que varíen por iniciativa propia tras su instanciación, cualquier actualización visual futura se produce cuando su widget padre reconstruye la interfaz con nuevas propiedades, haciendo innecesaria la sobrecarga de un objeto State separado.

A2. Propiedades, Valores por Defecto y Accesibilidad

2.1 y 2.2 Propiedades y Validaciones por Aserción

Para otorgar versatilidad al selector, se han añadido propiedades configurables con valores por defecto bien definidos:

Propiedad Tipo Por Defecto Validación mediante assert
min int 0 assert(min < max, 'min debe ser menor que max')
max int 10 assert(min < max, 'min debe ser menor que max')
step int 1 assert(step > 0, 'step debe ser mayor que 0')
initialValue int igual a min assert(initialValue >= min && initialValue <= max)

2.3 Seguridad en Entornos de Producción (Release)

Puesto que los assert de Dart son descartados durante la compilación en modo release (--release), el componente implementa un mecanismo de clamping en tiempo de ejecución: 

// Protección activa incluso si se desactivan las aserciones:
_value = _value.clamp(widget.min, widget.max);

Asimismo, en el método didUpdateWidget se detecta si las cotas min o max cambian dinámicamente desde el widget padre, reajustando de inmediato el valor interno dentro de los nuevos márgenes.

2.4 Desactivación Reactiva de Botones

Siguiendo las directrices de diseño de Material Design, los botones se deshabilitan explícitamente cuando no existe posibilidad de continuar la operación, asignando null a su propiedad onPressed: 

final bool canDecrement = _value > widget.min;
final bool canIncrement = _value < widget.max;

IconButton(
  icon: const Icon(Icons.remove),
  onPressed: canDecrement ? () => _applyDelta(-widget.step) : null,
)
IconButton(
  icon: const Icon(Icons.add),
  onPressed: canIncrement ? () => _applyDelta(widget.step) : null,
)

A3. Eventos Propios y Manejo de Límites

3.1 Emisión de Cambios con onChanged

Se ha provisto la propiedad final ValueChanged<int>? onChanged;. Cuando el usuario pulsa un botón y la operación modifica el valor numérico, se notifica inmediatamente a la función callback suministrada con el nuevo entero.

3.2 y 3.3 Definición de Tipos y Evento onLimitReached

Se formalizó la estructura para la notificación de llegada a extremos mediante un tipo enumerado y un alias de función (typedef): 

/// Límites alcanzables por [QuantityStepper].
enum StepperLimit { min, max }

/// Firma del callback para la notificación de límites.
typedef LimitReached = void Function(StepperLimit limit);

El widget expone la propiedad final LimitReached? onLimitReached;. Cuando el valor alcanza la cota superior widget.max, se invoca onLimitReached?.call(StepperLimit.max). Si alcanza la cota inferior widget.min, se invoca onLimitReached?.call(StepperLimit.min).

3.4 Ausencia de Eventos si el Valor no Cambia

Para salvaguardar el rendimiento y evitar eventos duplicados o redundantes, la función interna _applyDelta realiza una comparación previa: 

final nextValue = nextStepperValue(
  current: _value,
  delta: delta,
  min: widget.min,
  max: widget.max,
);

if (nextValue == _value) {
  return; // No se muta el estado ni se emite ningún callback
}

A4. Pruebas Unitarias, de Widget, Golden y Cobertura

4.1 Función Pura nextStepperValue

Para favorecer una arquitectura desacoplada y comprobar el cálculo de valores de forma determinista y sin efectos secundarios, el algoritmo de cómputo se extrajo como una función pura independiente: 

int nextStepperValue({
  required int current,
  required int delta,
  required int min,
  required int max,
}) {
  final next = current + delta;
  if (next < min) return min;
  if (next > max) return max;
  return next;
}

Se redactaron 6 pruebas unitarias específicas que cubren: incremento ordinario, decremento ordinario, tope en límite superior, salto con step mayor que el margen hasta max, tope en límite inferior y salto negativo acotado a min.

Incidencia técnica identificada y analizada: Durante la ejecución inicial en el entorno local, se observó que la herramienta pub del SDK de Dart (fichero package:pub/src/io.dart createTarGz) presenta un fallo conocido de codificación de rutas cuando el directorio padre contiene caracteres de espacio en blanco (transformando actividad 2 tema 3 en actividad%202%20tema%203 y generando un error de discrepancia de rutas relativas). Para garantizar la máxima interoperabilidad y robustez tanto en sistemas de integración continua como en proyectos dependientes, se estructuró la raíz del paquete de manera canónica sin espacios, logrando una validación impecable con 0 avisos.
